LangGraph Pipeline  ·  5-node state machine
Node 1
Detect Framework
The LLM reads a snippet from each file and identifies the web framework and programming language. Returns a structured JSON response.
FastAPI Flask Django REST Express Koa Go-gin Go-fiber Spring Boot
Fallback: keyword-based detection if LLM output is unparseable
framework + language
Node 2
Extract Endpoints
Each file is processed in 4 000-character chunks. The LLM extracts every route it finds and returns a structured JSON array. Duplicates are removed by METHOD:PATH key.
  • HTTP method (GET / POST / PUT / DELETE / PATCH)
  • URL path with path parameters
  • Query parameters — name, type, required
  • Request body schema description
  • Response schema description
  • Authentication required flag
  • Tags for grouping
  • Function name + one-line summary
structured endpoint list
Node 3
Generate Markdown Documentation
Endpoints are grouped by tag. The LLM writes a full documentation block for each route following a strict Markdown template.
Endpoint heading + summary 2–3 sentence description Parameters table Request body Response codes table HTTP example with auth header
markdown document
Node 4
Generate OpenAPI 3.0 YAML
The LLM produces a complete OpenAPI 3.0.0 specification from the extracted endpoint list.
  • info block — title, version, servers
  • All paths with operations
  • requestBody for POST / PUT / PATCH
  • 200 / 400 / 401 / 404 / 500 responses
  • components/schemas section
  • Tags array per operation
Fallback: minimal YAML builder if LLM output fails validation
OpenAPI YAML spec
Node 5
AI Quality Review
A final LLM pass audits the generated documentation and returns structured feedback.
Vague or missing descriptions Parameters missing type or requirement Missing authentication notes Undocumented error scenarios Naming inconsistencies
Returns: Review Summary  ·  Issues Found  ·  Concrete Suggestions
