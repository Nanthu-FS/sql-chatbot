# Dither Farm art spec

All art is generated by code in `Tools/ArtGen` and written to `app/src/main/assets/art/`.
Nothing is hand-painted in an image editor, so every sprite can be regenerated.

## Look
- **Palette:** Endesga-32 only (see `pixelize.py`). Outline and darkest shade: `#181425`.
- **Style:** 32px-scale pixel art with checker (Bayer) dithering between palette colours, a 1px black outline, and a hard drop shadow (dark, ~35% alpha) offset 1px right and 1–2px down.
- **Light** comes from the top-left: highlights on top/left faces, darker shades and dither on bottom/right.
- **Readability first.** Silhouettes must read at 1x: chunky shapes, nothing thinner than 2px before outlining. Use thin details only as single highlight pixels.
- **Isometric:** 2:1 pixel lines (2 across, 1 down). The tile diamond is 32×16.

## Two ways to make a sprite
1. **Vector to pixel** (`lib/<group>.mjs`): draw soft vector art (no outlines, flat or simple gradient fills) and let `pixelize.py` quantise, dither, outline and shadow it. Best for organic shapes: crops, produce, trees, food, icons. `build()` returns `{ name, asset, px, pivot, style }` (see `generate.mjs`).
2. **Pixel-direct** (`pixel/<group>.py`): set pixels with PIL. Best for things that must line up exactly: iso ground tiles, fences, 9-slice UI frames, bars, cursors. The script takes the art dir as `argv[1]`, writes its PNGs, and prints a JSON object of pivots `{ "group/name": {"ax": .., "ay": ..} }`. Shared helpers live in `pixel/_pix.py`.

Run `node generate.mjs <group>` and review the 4x contact sheet in `Docs/sheets/<group>.png`.

## Sizes and pivots
| Folder | Contents | Size (before 2px pad) | Pivot |
|---|---|---|---|
| `tiles/` | ground diamonds (grass, soil, paths, water, rock floor) | 32×16 top face, +4–8px side for raised soil | top corner (16, 0) |
| `crops/` | `<crop>_<stage>`: 0 seeds, 1 sprout, 2 growing, 3 ready, `_dead` withered | 32 wide, ≤40 tall | soil contact at tile centre |
| `items/`, `items_big/` | inventory items | 14 / 28 square | centre |
| `icons/`, `icons_big/` | HUD/UI icons | 14 / 28 square | centre |
| `trees/` | forest trees, saplings, stumps | 32–48 wide, ≤64 tall | base of trunk |
| `rocks/` | quarry and mine rocks, ores, geodes, ladder | 24–32 wide | base centre |
| `machines/` | 1-tile machines | 32 wide, ≤40 tall | slot centre |
| `buildings/` | 2×2 / 3×3 slot buildings (barn, silo, greenhouse…) | 64 / 96 wide | footprint centre |
| `deco/` | fences, bushes, flowers, lanterns, signs | various | base |
| `ui/` | 9-slice frames, buttons, bars, tabs, toggles | 9-slice border 4–6px | top-left (0, 0) |
| `portraits/` | villager faces | 32×32 | centre |
| `fx/` | particles: sparkle, drop, leaf, chip, dust, coin | 4–12 | centre |

## Naming
- Lowercase `snake_case`; the item id from `GAME_DESIGN.md` is the file name (`items/iron_bar.png`).
- Animated sprites use `_a`, `_b` frame suffixes (`machines/sprinkler_a.png`).
- The engine falls back to a magenta checker for a missing name and logs it, so gaps are obvious in game.
